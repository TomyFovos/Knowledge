# Knowledge Graph

## 概要

ナレッジグラフ（Knowledge Graph / KG）は、知識を「もの」と「つながり」で表現する。

中心になるのは、実体・概念を表す **Node** と、それらの関係を表す **Edge** である。文字列の一致だけを見るのではなく、「誰がどの製品を担当するか」「ある障害がどのコンポーネントへ影響するか」のように、実体同士の関係を明示的に持つ。

LLMとの組み合わせで重要なのは、LLMが確率的に文章を生成する一方、KGでは定義されたエンティティIDと関係を参照できることにある。文章生成と、構造化された事実・関係の管理を分離できる。

## 基本モデル

KGの代表的な表現には二つある。

### RDF

RDFは知識を `Subject - Predicate - Object` のトリプルで表現する。

```text
<鈴木一郎> <担当する> <Project Alpha>
<Project Alpha> <予算承認者> <山田部長>
```

一つの事実を一つのトリプルとして積み上げ、複数のトリプルを連鎖させて知識を表現する。W3C標準との相互運用やLinked Dataを重視するときに向く。

### Property Graph

NodeとEdgeの双方に属性を持たせるモデル。Neo4jなどが代表例で、Cypherによるパス探索が使われる。

開発速度やスキーマの柔軟性を重視する場合、本資料ではProperty Graphから始める選択を推している。

## RDBとの違い

RDBが苦手なのは「関係を持つこと」そのものではない。関係を何段も辿る必要が生じたとき、JOINが増え、クエリとスキーマ変更の負担が大きくなる点にある。

KGでは関係自体が第一級のデータなので、多段の関係探索をパスとして記述できる。

一方、集計・トランザクション・固定された構造ではRDBが適する。実システムでは、請求やユーザー情報をRDB、関係性や権限・知識構造をKGに置くような共存が現実的である。

## Vector DBとの違い

Vector DBは埋め込み空間における「意味の近さ」を扱う。類似文書や関連文書を探すことに強い。

KGは「構造として定義された関係」を扱う。どの経路でつながるか、何が存在しないか、何件あるか、といった問いを扱いやすい。

つまり、

- Vector DB: 意味検索
- KG: 構造推論・パス探索

という役割の違いがある。どちらか一方へ統一するのではなく、用途で使い分ける。

## AIにとっての価値

本資料はKGがAIにもたらす価値を、主に次の三つとして整理している。

1. **推論の透明性** — 関係を辿ることで根拠を追跡できる
2. **更新性** — 学習済みモデルを再学習せず、知識側を更新できる
3. **LLMへの依存低減** — 金額・契約・権限など、間違えてはいけない情報を構造化データから直接取得できる

KGは「LLMの代替」ではない。LLMが自然言語を扱い、KGが関係と事実を保持するという役割分担に価値がある。

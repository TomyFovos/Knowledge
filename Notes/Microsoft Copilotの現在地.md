# Microsoft Copilotの現在地

Microsoft Copilotと聞くと、WindowsのCopilotキーから呼び出して質問する、少し精度の低いチャットAIを思い浮かべる人がいる。
少し前に触った印象で止まっているなら、それも不思議ではない。
しかし元資料の筆者が調べ直したところ、現在の **Microsoft 365 Copilot** は当時とかなり違うものになっていた。

現在のMicrosoft 365 Copilotは、Microsoft版ChatGPTを作ろうとしているわけではない。
Microsoft 365に蓄積されたメール、会議、チャット、資料、業務データをAIが利用し、その会社で行われている仕事を踏まえて回答したり、実際の作業を進めたりする方向へ広がっている。

元資料は社内向け記事の第1回であり、筆者の評価や注目点を含む。
機能、提供時期、料金体系は記録時点（2026年9月）の整理であり、変更される可能性がある。

## 選べるAIモデルはMicrosoft独自ではない

分かりやすく変わったのは、Copilotから使えるAIモデルである。
現在はOpenAIのGPT系モデルだけでなく、AnthropicのClaude SonnetやOpusなどもMicrosoft 365 Copilotへ入っている。
2026年時点ではGPT-5.6のような新しいモデルも利用対象になっている。

つまり、「MicrosoftのAIだからMicrosoft独自のAIモデルを使う」という構成ではない。
以前のCopilotに「ChatGPTやClaudeと比べると、使っているAIそのものが弱い」という印象を持っていたなら、認識を更新した方がよい。

ただし、変わったのはモデルだけではない。
より大きいのは、AIが質問に答えるだけでなく、Microsoft 365の中で仕事そのものを扱い始めていることである。

## CoworkはOfficeの成果物まで作るエージェント機能である

**Cowork** は、質問に文章を返すだけでなく、Microsoft 365にある情報を調べながら複数の作業を進め、成果物まで作るための **エージェント（Agent）機能** である。
筆者が最も注目している機能である。

たとえば次の仕事を、一つの依頼として渡せる。

```text
関連資料を探す
↓
内容を整理する
↓
その情報を使って Excel を編集する / Word 文書を作る / PowerPoint 資料へまとめる
```

Cowork自体は2026年6月に一般提供された。
9月に発表された新しいCopilotでは、通常のChatとCoworkをより近い場所から使える構成へ整理されている。

## PowerPointを直接扱えることが他社AIとの違いになる

筆者が特に気にしているのはPowerPointである。

ChatGPTやClaudeにも、情報を調べて文章やファイルを生成する能力はある。
しかしMicrosoftはPowerPointそのものを提供しているため、AIが最終的なOffice成果物へ直接手を入れられる。

企業では、AIが良い文章を生成できても、最後に人間がPowerPointへコピーし、レイアウトを整え、既存資料へ合わせる作業が残ることがある。
Coworkでこの工程まで任せられるなら、単なる文章生成より業務への影響は大きくなる。

WordやExcelにも同じ強みはある。
ただ、最終成果物としてそのまま共有することが多いPowerPointでは、Microsoft製品を直接操作できる利点が特に分かりやすく表れる、というのが筆者の見立てである。

## Codeは開発者向けではなく、業務アプリを自分で作る機能である

2026年9月25日には **Code** という機能も発表された。
名前からGitHub Copilotのような開発者向けコーディングツールを想像しやすいが、狙っている利用者は少し違う。

CodeはGitHub Copilotと共通する技術を使いながら、自然言語で指示して、自分の仕事に必要な小さなアプリや業務ツールを作れるようにする機能である。
いわゆる **バイブコーディング（Vibe Coding）**、つまり会話で指示しながらAIに実装させる進め方を、エンジニア以外へ広げる機能に近い。

| 用途 | 使う環境 |
| --- | --- |
| 本格的なソフトウェア開発 | GitHub Copilotなどの開発者向け環境 |
| ちょっとした業務アプリを自分で作る | Code |

筆者は、現時点ではCodeをCoworkほど注目していない。
すでに社内で開発手段を持っている場合、Codeでなければ解決できない問題はまだ少なく見えるためである。

## Microsoft IQはAIへ会社のコンテキストを渡す仕組みである

CoworkやCodeだけを見ると、Microsoftも他社と同じようにAIエージェントを増やしているように見える。
しかし筆者は、Copilotの方向性を理解するうえでは、その下にある **Microsoft IQ** の方が興味深いとしている。

Microsoft IQは、企業のAIが利用する情報を、その性質に応じて四つの領域として扱う考え方である。

| 領域 | 扱う情報 | 例 |
| --- | --- | --- |
| **Work IQ** | その人がどのような仕事をしているかを理解するための情報 | Outlookのメール、Teamsの会議やチャット、SharePointやOneDriveのファイル、人との共同作業 |
| **Fabric IQ** | 業務データを、その会社にとっての意味や関係とともに扱う | 売上、顧客、在庫 |
| **Foundry IQ** | 組織として管理し、AIから再利用したい知識 | 社内規程、正式文書、ナレッジベース（Knowledge Base） |
| **Web IQ** | 社内だけでは得られない情報 | ニュース、Web上の最新情報 |

細かな機能を一つずつ覚えるより、「AIへ会社の **コンテキスト（Context）**、つまり判断の前提となる状況や事情を渡す仕組みが、Microsoft製品群の中に作られ始めている」と捉えると理解しやすい。

これにより、使い方が次のように変わる。

```text
一般的な知識を持つAIに、毎回会社の事情を説明する
↓
その会社で今行われている仕事をある程度理解したAIへ相談する
```

## Microsoft 365を使ってきた履歴がコンテキストになる

この構造では、Microsoft 365を長く使ってきた会社が持つ情報の意味も変わる。

たとえば、Outlookでメールを送り、Teamsで会議やチャットを行い、SharePointへ資料を保存してきたとする。
これまでは、人間が必要になったときに検索して開くための情報だった。
Work IQでは、それらがAIに仕事を理解させるためのコンテキストとして使われる。

- 誰が案件に関わっているか。
- 最近どの資料を使っているか。
- どの会議やメールが現在の仕事と関係しているか。

こうした情報を、人間が毎回すべてプロンプトへ書く必要が減る。

AI導入後に「自社専用AI用のデータ」を一から用意するだけではない。
これまでMicrosoft 365で仕事をしてきた履歴そのものが材料になる。
対象はSharePointに残した資料だけではなく、OutlookやTeamsまで含めて仕事のコンテキストを作れる。
ここに、Microsoftが企業向けAIを提供する強みがある。

## 記録に残らなかったことはAIも知らない

ただし、「会社で起きたことを何でも知っている」という意味ではない。

たばこ休憩中に二人で話して決めたことが、メールにもTeamsにも議事録にも残らなかったなら、その判断をWork IQが知る材料はない。
AIが利用できるのは、Microsoft 365をはじめとした接続先へ残った情報だけである。

同じ理由で、「新しい決定が一度記録されれば、過去の決定を必ず無視してくれる」と考えるのも危険である。
現在の仕事との関連性や情報の新しさを考慮する仕組みはある。
しかし、どの文書を正式な規程として扱うか、古い決定をいつ無効とみなすかという **ナレッジ管理（Knowledge Management）** は、Foundry IQなども含めて会社側で設計する必要がある。

## Copilotは既存のアクセス権の範囲で情報を使う

会社の情報をここまでAIへ渡すなら、「他人の資料までAIが勝手に読んでしまわないか」が気になる。

Microsoft 365 Copilotは、Microsoft 365にすでに設定されているユーザーのアクセス権を基礎に情報を利用する。
ある社員には閲覧できるSharePoint資料があり、別の社員にはその権限がない場合、後者のCopilotがWork IQを通じて勝手にその資料を使えるようになるわけではない。

したがって、AI専用の権限管理を一から作るより、既存のMicrosoft 365側の権限を正しく整備することが先になる。

## Entra IDの有料化はCopilotのためではなく、セキュリティ強化の判断である

筆者の社内では、現在 **Entra ID**（Microsoftのアカウントとアクセス管理の基盤）の無料版を使っていると聞いている。
**条件付きアクセス（Conditional Access）** などを含め、今後どこまでアクセス条件を細かく管理する必要があるかは、情シスと確認したい事項である。
より高度な制御が必要になれば、Entra IDの有料プランを検討する余地がある。

ただし、次の二つは別の話である。

- 「ユーザーが見られる情報の範囲でCopilotも情報を利用する」という基本動作。
- 「Entra IDを有料版へ変更する」という判断。

有料版への変更は、Copilotを動かすためではない。
Microsoft 365全体のアクセス制御やセキュリティをどこまで強化するかという判断になる。

## 会社の経験を知識へ変える部分は残る

Work IQで現在の仕事を理解し、Foundry IQで管理されたナレッジをAIへ渡せるようになっても、仕事で起きた成功、失敗、判断変更そのものが、自動的に次の仕事で使える組織知へ変わるわけではない。

そこで筆者が作っているのが **DevLore** である。
DevLoreはMicrosoft Copilot専用の拡張機能ではない。
レビュー記録や成果物などから仕事の経験を整理し、次の仕事で再利用できるナレッジへ変える独立した仕組みとして設計している。

```text
Microsoft Copilot側：検索、現在の仕事のコンテキスト、権限管理
DevLore側        ：そこから先の知識循環（経験 → 再利用できるナレッジ）
```

Copilotを使う場合は、Microsoftが得意な部分をCopilotへ任せ、DevLoreが知識循環を補う構成にできる。
Microsoftを使わない場合でも、別の情報源やAIと接続して同じ役割を持たせる前提である。

Copilotが「会社のことを知る」ところまで進んだ後、会社が「仕事から学ぶ」には何が必要か。
この問いは続編で扱われている（[[AIを使う会社から、経験を蓄積できる会社へ|AIを使う会社から経験を蓄積できる会社へ]]）。

## 料金は三つに分けて確認する

現在のMicrosoft Copilotは、「Copilotを契約すれば、紹介した機能をすべて無制限に使える」という構成ではない。
以下は記録時点（2026年9月）の整理である。

| 区分 | 内容 |
| --- | --- |
| **Microsoft 365 Copilot**（ユーザーライセンス） | Copilot Chatや、Word、Excel、PowerPoint、Outlook、Teamsなどから使う日常的なCopilotの基礎 |
| **Copilot Credits**（従量課金） | Coworkなど、AIが複数工程をエージェントとして実行する処理で意識する必要がある |
| **Entra ID**（管理基盤） | Copilotとは別に、アクセス制御やセキュリティをどこまで強化するかで有料プランを検討する |

Codeも高度なエージェント処理を使うため、通常のチャットとは料金の考え方を分けて確認する必要がある。

確認したい事項は次のとおりである。

- Coworkが実際の作業でどの程度Creditsを消費するか。今回の機能の中で業務への影響が大きそうなため、特に確認したい。
- 自社で現在契約しているMicrosoft 365 Businessのプランに、Microsoft 365 Copilotをどの契約形態で追加するか。情シスへの確認が必要である。
- Entra IDを無料版から有料版へ変更するか。これはCoworkを使うためではなく、Conditional Accessをはじめとしたアクセス制御やセキュリティ強化のための判断である。

Coworkを一部の実験用途ではなく日常業務で広く使うなら、従量課金額だけでなく、それによって削減できる作業まで含めてプランを検討することになる。

導入時は、ユーザーライセンス、Coworkなどの従量課金、Entra IDを含む管理基盤の三つを分けて確認すると、実際に何へ費用がかかるかを整理しやすい。

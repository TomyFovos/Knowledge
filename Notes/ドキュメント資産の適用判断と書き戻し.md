# ドキュメント資産の適用判断と書き戻し

既存の規程、手順、Template、過去成果物をAI開発で利用するときは、「検索で見つかったこと」と「今回従うべきこと」を分離する。保存場所やファイル形式の違いはAdapterへ閉じ込め、AI-DE CoreとはDocument Asset Portを境界にする。

このノートは2026-08-27の引継ぎ条件を整理したものである。文書資産の内部モデルが完成した設計書ではなく、利用側の境界と、今後決めるべき論点を記録している。

## 接続境界

```text
AI-DE Core
    ↓ Document Asset Port
ローカル実装 / 外部サービス
    ↓ Adapter・Codec
Git / SharePoint / ファイルサーバー / XLSX / DOCX / Markdown
```

実装が同じRepository内か別サービスかによってCore側の利用方法が変わらない設計を目指す。

| やり取り | 最低限必要なもの |
|---|---|
| AI-DEから渡すContext | Project、Work Item、Phase、Task、変更対象、Repository・Path・Component、Team、実行目的、必要Artifact種別等 |
| 安定した参照 | `asset_id`とrevision / version |
| 本文 | 内容または取得できる参照 |
| 適用結果 | applicable / not_applicable / requires_human_decision等。名称・Schemaは未確定 |
| 判断根拠 | なぜ使うかをEvidence / Auditへ残せるDecision Trace |
| Capability | 検索、読取、適用解決、Import、Write-back、版確認、競合検出等の対応範囲 |

## 意味上の操作

1. Discover / Search：関連しそうな資産を探す。
2. Resolve：今回の規範、参考、人間判断が必要なものを区別する。
3. Read：特定のAsset Revisionを読む。
4. Import：既存資料を取り込み、Identity・原本・Parsed Representationの関係を管理する。
5. Write-back：元形式へ戻し、外部編集との競合、承認、版、失敗を扱う。

具体的なAPI名は凍結されていない。Authority・Scope・Binding・Freshness等の解決ロジックは資産側の責務にする。

## Authorityを単純な検索順位にしない

| 論点 | 決めること |
|---|---|
| Classification | 規範、Team Playbook、Template、Exemplar、Project Artifact等の分類 |
| Authority | 必須Rule・Process、推奨、参考の違い |
| Scope / Binding | どの組織・案件・Path・工程へ、誰が正式に適用したか |
| Precedence / Conflict | 自動解決、人間判断、Fail Closedの条件 |
| Freshness / Lifecycle | 日時だけでなくactive・superseded・retired等をどう判断するか |
| Ownership / Provenance | 作成・承認・更新の権限と出所 |
| Promotion / Exception | 過去事例の正式な昇格と、期限・範囲付き例外 |

上表の候補分類や状態名は今後の設計対象である。検索Scoreや更新日時、一つのPriority番号ですべてを決めない。過去の成功例をAIが自動で規範へ昇格させない。

## 書き戻しと証拠

元のXLSX / DOCX等へ戻す際は、形式維持、revision確認、外部編集とのConflict、Atomicity、Approval、Failureを設計する。取り込みと書き戻しを同じAsset Identityで追えることが必要になる。

Evidenceには、どの資産のどの版を、なぜ使用し、どのRuleが適用され、人間判断があったかを残す。大量の文書をContextへ投入する代わりに、適用される資産と必要な部分だけを渡す。

## 未決の範囲

最終Schema、Authorityの段階、優先・競合規則、保存先、検索エンジン、Vector DB、Connector / Codec、Write-backの詳細は未確定。引継ぎ資料はこれらを別設計で決める条件であり、今回の取り込みで設計や接続を実行したものではない。

2026-08-25の設計凍結資料にもAssetのAuthorityをBinding由来とする整理があるが、具体的なDocument Asset実装が完成した証拠としては使わない。

MICROSOFT 365 COPILOT

Microsoft Copilot、今はこんなことになっている

Microsoft Copilotと聞くと、WindowsのキーボードにあるCopilotキーから呼び出して質問する、少し精度の低いチャットAIを思い浮かべる人もいると思います。

少し前に触ったときの印象で止まっているなら、それも不思議ではありません。

私自身も似た認識を持っていましたが、最近のMicrosoft Copilotを調べてみると、当時とはかなり違うものになっていました。

現在のMicrosoft 365 Copilotは、単にMicrosoft版ChatGPTを作ろうとしているわけではありません。
Microsoft 365に蓄積されたメール、会議、チャット、資料、業務データをAIが利用し、その会社で行われている仕事を踏まえて回答したり、実際の作業を進めたりする方向へ広がっています。

選べるAIモデルも変わっている

まず分かりやすく変わったのが、Copilotから利用できるAIモデルです。

現在はOpenAIのGPT系モデルだけでなく、AnthropicのClaude SonnetやOpusなどもMicrosoft 365 Copilotへ入ってきています。

2026年時点ではGPT-5.6のような新しいモデルも利用対象になっており、「MicrosoftのAIだからMicrosoft独自のAIモデルを使う」という構成ではありません。

そのため、以前のCopilotに対して「ChatGPTやClaudeと比べると、使っているAIそのものが弱い」という印象を持っていた場合は、一度認識を更新した方がよさそうです。

ただし、現在のCopilotで変わっているのはモデルだけではありません。

むしろ大きいのは、AIが質問に答えるだけではなく、Microsoft 365の中で仕事そのものを扱い始めていることです。

Officeを動かすCowork

注目している機能

Coworkは、質問に対して文章を返すだけではなく、Microsoft 365にある情報を調べながら複数の作業を進め、成果物まで作るためのAgent機能です。

例えば、関連資料を探して内容を整理し、その情報を使ってExcelを編集したり、Word文書を作ったり、PowerPointの資料へまとめたりする仕事を、一つの依頼として渡せます。

Cowork自体は2026年6月に一般提供されており、9月に発表された新しいCopilotでは、通常のChatとCoworkをより近い場所から使える構成へ整理されています。

私が特に気になっているのはPowerPointです。

ChatGPTやClaudeにも、情報を調べて文章やファイルを生成する能力はありますが、MicrosoftはPowerPointそのものを提供しているため、AIが最終的なOffice成果物へ直接手を入れられます。

企業では、AIが良い文章を生成できても、最後に人間がPowerPointへコピーし、レイアウトを整え、既存資料へ合わせる作業が残ることがあります。

Coworkでこの工程まで任せられるのであれば、単なる文章生成より業務への影響は大きくなります。
WordやExcelにも同じ強みがありますが、最終成果物としてそのまま共有することの多いPowerPointでは、Microsoft製品を直接操作できる利点が特に分かりやすく表れそうです。

小さな業務アプリを作るCode

2026年9月25日には、Codeという機能も発表されました。

名前からGitHub Copilotのような開発者向けコーディングツールを想像しやすいのですが、狙っている利用者は少し違います。

CodeはGitHub Copilotと共通する技術を利用しながら、自然言語で指示して、自分の仕事に必要な小さなアプリや業務ツールを作れるようにする機能です。

本格的なソフトウェア開発をする場合はGitHub Copilotなどの開発者向け環境を使い、Codeは「ちょっとした業務アプリを自分で作る」という用途へ寄せて考えた方が分かりやすいと思います。

いわゆるバイブコーディングを、エンジニア以外にも広げる機能に近いでしょう。

個人的には、現時点ではCoworkほど注目していません。

すでに社内で開発手段を持っている場合、Codeでなければ解決できない問題はまだ少なく見えるためです。

Microsoft IQという考え方

CoworkやCodeだけを見ると、Microsoftも他社と同じようにAI Agentを増やしているように見えます。

しかし、Microsoft Copilotの方向性を理解するうえでは、その下にあるMicrosoft IQの方が興味深いと感じています。

Microsoft IQは、企業のAIが利用する情報を、その性質に応じて四つの領域として扱う考え方です。

Work IQ

Outlookのメール、Teamsの会議やチャット、SharePointやOneDriveのファイル、人との共同作業などから、その人がどのような仕事をしているのかを理解するための情報を扱います。

Fabric IQ

売上、顧客、在庫といった業務データを、その会社にとっての意味や関係とともに扱います。

Foundry IQ

社内規程や正式文書、Knowledge Baseなど、組織として管理してAIから再利用したい知識を扱います。

Web IQ

社内だけでは得られないニュースやWeb上の最新情報を扱います。

細かな機能を一つずつ覚えるより、まずは「AIへ会社のContextを渡す仕組みが、Microsoft製品群の中に作られ始めている」と捉えると理解しやすくなります。

一般的な知識を持つAIに毎回会社の事情を説明する使い方から、その会社で今行われている仕事をある程度理解したAIへ相談する使い方へ変わっていくからです。

Microsoft 365を使ってきた履歴がContextになる

この構造では、Microsoft 365を長く使ってきた会社が持つ情報の意味も変わります。

例えば、会社でOutlookを使ってメールを送り、Teamsで会議やチャットを行い、SharePointへ資料を保存してきたとします。

これまでは、人間が必要になったときに検索して開くための情報でした。

Work IQでは、それらがAIに仕事を理解させるためのContextとして利用されます。

誰が案件に関わっているのか、最近どの資料を使っているのか、どの会議やメールが現在の仕事と関係しているのかといった情報を、人間が毎回すべてプロンプトへ書く必要を減らせます。

AI導入後に「自社専用AI用のデータ」を一から用意するだけではなく、これまでMicrosoft 365を使って仕事をしてきた履歴そのものが材料になります。

SharePointに残した資料だけが対象なのではありません。

OutlookやTeamsまで含めて仕事のContextを作れるところに、Microsoftが企業向けAIを提供する強みがあります。

ただし、「会社で起きたことを何でも知っている」という意味ではありません。
たばこ休憩中に二人で話して決めたことが、メールにもTeamsにも議事録にも残らなかったのであれば、その判断をWork IQが知るための材料はありません。

AIが利用できるのは、あくまでMicrosoft 365をはじめとした接続先へ残った情報です。

同じ理由で、「新しい決定が一度記録されれば、過去の決定を必ず無視してくれる」と考えるのも危険です。

現在の仕事との関連性や情報の新しさを考慮する仕組みはありますが、どの文書を正式な規程として扱うのか、古い決定をいつ無効とみなすのかというKnowledge管理は、Foundry IQなども含めて会社側で設計する必要があります。

既存の権限をCopilotでも使う

会社の情報をここまでAIへ渡すのであれば、次に気になるのは「他人の資料までAIが勝手に読んでしまわないのか」という点です。

Microsoft 365 Copilotは、Microsoft 365にすでに設定されているユーザーのアクセス権を基礎に情報を利用します。

例えば、ある社員には閲覧できるSharePoint資料があり、別の社員にはその権限がない場合、後者のCopilotがWork IQを通じて勝手にその資料を利用できるようになるわけではありません。

AI専用に別の権限管理を一から作るより、既存のMicrosoft 365側の権限を正しく整備することの方が先になります。

社内では現在Entra IDの無料版を使っていると聞いているため、Conditional Accessなどを含め、今後どこまでアクセス条件を細かく管理する必要があるかは情シスと確認したいところです。

より高度な制御が必要になれば、Entra IDの有料プランを検討する余地があります。

ただし、「ユーザーが見られる情報の範囲でCopilotも情報を利用する」という基本動作と、「Entra IDを有料版へ変更する」という話は別です。

有料版への変更は、Copilotを動かすためではなく、Microsoft 365全体のアクセス制御やセキュリティをどこまで強化するかという判断になります。

会社の経験を知識へ変える部分は残る

Work IQによって現在の仕事を理解し、Foundry IQによって管理されたKnowledgeをAIへ渡せるようになっても、 仕事で起きた成功、失敗、判断変更そのものが、自動的に次の仕事で使える組織知へ変わるわけではありません。

そこで現在作っているのが DevLore です。 DevLoreはMicrosoft Copilot専用の拡張機能ではなく、レビュー記録や成果物などから仕事の経験を整理し、 次の仕事で再利用できるKnowledgeへ変える独立した仕組みとして設計しています。

Microsoft Copilotを利用する場合は、Microsoft側が得意な検索、現在の仕事のContext、権限管理を任せ、 DevLoreはそこから先の知識循環を補う構成にできます。 Microsoftを利用しない場合でも、別の情報源やAIと接続して同じ役割を持たせる前提です。

Copilotが「会社のことを知る」ところまで進んだあと、会社が「仕事から学ぶ」には何が必要なのか。 その話を次のページで考えます。

料金は機能ごとに考える必要がある

現在のMicrosoft Copilotは、「Copilotを契約すれば、紹介した機能をすべて無制限に利用できる」という構成ではありません。

Microsoft 365 Copilot

Copilot Chatや、Word、Excel、PowerPoint、Outlook、Teamsなどから使う日常的なCopilotの基礎になります。

Copilot Credits

Coworkなど、AIが複数工程をAgentとして実行する処理では従量課金を意識する必要があります。

Entra ID

Copilotそのものとは別に、アクセス制御やセキュリティをどこまで強化するかで有料プランを検討します。

Codeについても、高度なAgent処理を利用するため、通常のチャットとは料金の考え方を分けて確認する必要があります。

特にCoworkは、今回見た機能の中でも業務への影響が大きそうなので、実際の作業でどの程度Creditsを消費するのかは確認しておきたいところです。

自社で現在契約しているMicrosoft 365 Businessのプランと、Microsoft 365 Copilotをどの契約形態で追加することになるのかについても、情シスへの確認が必要です。

Coworkを一部の実験用途ではなく、日常業務の中で広く利用するのであれば、従量課金額だけを見るのではなく、それによって削減できる作業まで含めてプランを検討することになります。

Entra IDについては別の費用です。

現在の無料版から有料版へ変更するとすれば、Coworkを使うためではなく、Conditional Accessをはじめとしたアクセス制御やセキュリティを強化するための判断になります。

したがって、導入時にはMicrosoft 365 Copilotのユーザーライセンス、Coworkなどの従量課金、Entra IDを含む管理基盤の三つを分けて確認した方が、実際に何へ費用がかかるのかを整理しやすくなります。

2026年9月時点の整理です。Microsoft 365 Copilotの機能、提供条件、料金体系は変更される可能性があります。

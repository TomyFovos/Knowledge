## 1. 概要

Olmo-core は、Ai2（Allen Institute for AI）が公開する Python ライブラリです。PyTorch の上に作られており、言語モデル OLMo の学習に使うコードが入っています。【確認】

要点は次の4つです。

- OLMo は、完成したモデルに加えて、学習データ、学習コード、手順、途中経過まで公開する「完全公開」の言語モデル群です。【確認】
- Olmo-core は、その学習コードにあたります。公式ドキュメントによると、元の OLMo の学習・モデルコードを、性能と API の安定を重視して書き直したものです。【確認】
- 実験は、設定を書き、`build()` で部品を作り、`trainer.fit()` で学習を始める形に統一されています。【確認】
- 学習の仕組みを本格的に学ぶ教材としては良い一方で、最初の入門教材としては環境と前提知識の負担が重いと考えられます。【検討】

## 2. 理解に必要な前提

- **言語モデル**：文章の続きを予測するように学習した AI。ChatGPT のような対話 AI の土台になる。
- **重み（パラメータ）**：学習で調整される数値。モデルの中身にあたる。「32B」は約320億個を表す。
- **トークン**：文章を細かく区切った単位。学習量はトークン数で表すことが多い。OLMo 2 は最大6兆トークンで学習している。【確認】
- **学習率**：1回の更新で、モデルをどれだけ動かすかを決める値。
- **チェックポイント**：学習の途中経過を保存したもの。続きから再開したり、途中の状態を調べたりできる。
- **オープンウェイトと完全公開**：オープンウェイトは、完成したモデルの重みだけを公開する。完全公開は、データ、コード、手順、途中経過、評価まで公開する。
- **torchrun**：PyTorch の起動コマンド。1つの学習を複数の GPU に分けて実行する。
- **Beaker**：実験を実行するための基盤。Olmo-core の起動モジュールが対応先の例として挙げている。【確認】

## 3. 解説

### 3.1 OLMo の位置づけ

OLMo は「Open Language Model」の略です。Llama や Gemma のようなオープンウェイト型と違い、学習データ、道具、作り方の手順まで公開しています。【確認】OLMo 2 は Apache 2.0 ライセンスで、調べる、改造する、土台にして作ることができます。【確認】

最初の OLMo では、学習中に1000ステップごとに保存した500個を超えるチェックポイントが、各モデルについて公開されました。【確認】最新の OLMo 3 は、データから公開までの流れ全体を公開する方針で、完全公開では初めての32B「考える」モデルを含むと発表されています。【確認】

### 3.2 Olmo-core の構成

README によると、Olmo-core には次のものが入っています。【確認】

- モデルや学習の部品
- OLMo-2 と OLMo-3 の公式の学習スクリプト
- 学習済みモデルの文章生成（Hugging Face、vLLM での利用と、Olmo-core 自身のベータ版の生成機能、簡単なチャットのデモ）

モデルの評価は、別のリポジトリが担当します。【確認】

### 3.3 学習の組み立て

公式ドキュメントの流れは次のとおりです。【確認】

```
① 設定クラスを書く
   モデル / データセット / データローダー / 学習モジュール / トレーナー
        │  各設定に build() を呼ぶ
        ▼
② 部品ができる
   モデル ───────────▶ 学習モジュール（モデル＋更新の仕組み）
   データセット ─────▶ データローダー
   学習モジュール ＋ データローダー ─▶ トレーナー
        │  trainer.fit()
        ▼
③ 学習が進み、チェックポイントが保存される
        │
④（必要なら）起動用の設定で、複数の機械に送り出す
```

設定クラスは入れ物で、`build()` を呼ぶまで実際の部品は作られません。

学習モジュールは、モデルと、モデルを少しずつ良くする更新の仕組みをひとまとめにしたものです。トレーナーは、どの学習モジュールでも同じ窓口で扱い、学習のくり返し、保存、記録を管理します。【確認】学習のやり方を変えるときは、学習モジュールを差し替えます。【推測：ドキュメントの「さまざまな学習方式に対応できる」という説明からの解釈】

### 3.4 設定の上書き

設定クラスは Olmo-core の `Config` を継承しており、JSON として書き出せます。コマンドラインの指定で値を上書きすることもできます。【確認】README の例では、`--train_module.optim.lr=6e-3` を付けると、コードを編集せずに学習率を変えられます。研究者向けガイドには `--trainer.no_checkpoints` のような、同じ形の指定が載っています。【確認】

### 3.5 起動

README の例では、GPU 8枚の機械で OLMo-2 32B 用のスクリプトを `torchrun` で実行し、チェックポイントの保存先を指定すると学習が始まります。仕上げの工程は、保存済みのチェックポイントから続きを行う別のスクリプトが受け持ちます。【確認】Beaker 向けには、起動モジュールの設定を使います。【確認】

### 3.6 研究者向けの使い方

研究者向けガイドは、素早く実験するなら、依存ライブラリとして入れず、リポジトリを fork して使うことを勧めています。公式の Beaker 用イメージと、すべての依存を入れた Dockerfile も用意されています。【確認】

## 4. 似たものとの違い

| 観点 | OLMo / Olmo-core | オープンウェイト型（Llama、Gemma など） | 小さな自作・教育用の実装 |
|---|---|---|---|
| 公開の範囲 | 重み、データ、コード、手順、途中経過、評価 | 重みが中心 | コードが中心 |
| 学習の再現 | 公式スクリプトで同じ手順を試せる | 学習手順は公開されないことが多い | 小規模なら手元で試せる |
| 規模 | 実際に公開されたモデルの規模 | 非公開 | 小規模 |
| 学習の負担 | 大きい（GPU 複数枚が前提の例が中心） | 学習の再現は難しい | 小さい |

- 「オープンウェイト型は重みが中心」の点は、Ai2 の発表と報道で確認しています。【確認】
- 小さな自作・教育用の実装の列は、一般的な知識に基づく整理です。今回は個別の実装を調べていません。【推測】

## 5. 会話でわかったこと

### 5.1 OLMo の価値

資料から言えることは、次の3点です。

1. **理由を調べられる。**学習データが公開されているので、「どのデータが、どんな答え方につながるか」を確かめられます。プロジェクト責任者も、データが見られなければモデルの動作を科学的に調べられないという趣旨を述べています。【確認】
2. **途中経過を追える。**チェックポイントが公開されているので、完成品だけでなく、学習が進む様子も調べられます。【確認】
3. **自由に使い、作り直せる。**ライセンスとコードの公開により、自分のデータで同じ手順を試せます。【確認】

### 5.2 性能の見方

OLMo 2 32B について、Ai2 は、完全公開のモデルとして初めて、GPT-3.5-Turbo と GPT-4o mini を学術的なテスト群で上回ったと述べています。【確認：Ai2 自身の発表】OLMo の主な価値は、最新の商用 AI より強いことではなく、中身を公開して研究や自作に使えることです。【検討】

### 5.3 AI を作るための教材としての評価

- **向く点**：実際に公開モデルの学習に使われたコード、データ、手順、途中経過、評価がそろっています。小さな練習用コードでは見えない、現実の設計や判断を知れます。【検討】
- **向かない点**：動かす環境が重い（README の例は GPU 8枚）、設定クラスや分散学習など最初に覚えることが多い、大きなモデルを学習する費用や時間は再現できない、の3点です。【検討】
- **使い分けの目安**：まず小さな実装で学習の仕組みを理解し、そのあとで Olmo-core を読み、本格的に行うと何が増えるかを知る順番が向きます。入門用というより、入門のあとの次の教材です。【検討・推測】

# RustXNG ナレッジ

作成日：2026-11-02

## 1. 概要

RustXNG は、自分のサーバーで動かすメタ検索エンジンです。Google、Bing、Wikipedia、GitHub など多数の検索サイトに同じ検索語を同時に送り、返ってきた結果を1つにまとめて表示します。広告や追跡は入りません。

Python 製のメタ検索エンジン SearXNG を Rust で書き直したもので、検索の書き方、API の返し方、設定ファイルは SearXNG と互換になるように作られています。要点は次のとおりです。

- 配布物は単一のバイナリで、Python もデータベースも要らない
- SearXNG が標準で持つエンジン226種類をすべて移植済み（既定で有効なのは約170）
- README の実測では、起動0.03秒、メモリ13MiB（SearXNG は0.72秒、118MiB）
- ライセンスは AGPL-3.0-or-later
- 個人の開発で、公開から日が浅い（リリース記録の最初の公開版は10月18日、v0.4.1は10月26日）

## 2. 理解に必要な前提

**メタ検索エンジン**とは、自分では索引を持たず、他の検索サイトに問い合わせて結果を集める仕組みです。Google のように、ウェブを自分でたどって索引を作る検索エンジンとは別のものです。

**エンジン**とは、メタ検索の用語で、「あるサイトにどう問い合わせ、返事をどう読み取るか」を書いた手順の単位です。メタ検索エンジンが検索できるのは、エンジンが用意されたサイトだけです。

**SearXNG** は、オープンソースの代表的なメタ検索エンジンです。RustXNG はその互換実装にあたり、SearXNG の側を「上流」と呼びます。

## 3. 解説

### 3.1 1回の検索の流れ

```
検索語 → ①読み取る → ②一斉に送る → ③まとめる → ④返す
         !github など   各サイトへ同時    重複を除く     画面 / JSON
         の指定を解釈   に問い合わせ     順位をつける   CSV / RSS
```

1. **読み取る**：先頭の `!サイト名`、`!カテゴリ名`、`:言語`、`<待ち時間` などを解釈し、送り先を決める。指定がなければ既定で有効なエンジンに送る。
2. **一斉に送る**：各サイトへ同時に問い合わせる。エンジンはサイトごとにソースファイル1つで、返事の読み取り方を持つ。全体に制限時間があり、再試行は接続エラーのときだけ行う。落ちたサイトがあっても、残りの結果で返す。
3. **まとめる**：同じURLの結果を1つにし、順位をつけ、カテゴリごとに分ける。
4. **返す**：ブラウザ画面のほか、JSON、CSV、RSS で返す。

### 3.2 速さとプライバシー

速さについて、リリース記録には、全エンジンの検索が6.26秒から3.00秒に縮み、キャッシュとサイトの一時除外を使うと0.28秒（ウォーム時）になったと書かれています。主因は、時間切れの要求を再試行していたことでした。

プライバシーについては、画像とfaviconを RustXNG が代わりに取得するため、利用者のIPが相手のサイトに見えません。ただし、**検索語そのものは各サイトに直接送られます。**

運用向けの機能として、ヘルスチェック（`/healthz`）、メトリクス（`/metrics`）、統計（`/stats`）、設定画面（`/preferences`）、IPごとの回数制限、Valkey / Redis の共有キャッシュがあります。

### 3.3 使い方

```
# 起動（Rust 1.85以上）
cargo run --release -- --port 8888

# Docker
docker build -t rustxng .
docker run --rm -p 8888:8888 rustxng

# API
curl 'http://127.0.0.1:8888/search?q=rust&format=json'
curl 'http://127.0.0.1:8888/search?q=rust&time_range=day&format=json'
curl 'http://127.0.0.1:8888/search?q=%21github+tokio&format=json'
```

設定は、同梱の `settings.toml` が既定値です。変えたい項目だけを書いたファイルを `--config` に渡すと、既定値に上書きされます。API キーや自前サーバーが必要なエンジンは、最初は無効になっています。

## 4. 似たものとの違い

### 4.1 SearXNG との違い

同じ部分は、検索の書き方、URLのパラメータ名、`format=json` と `format=csv` の項目、設定ファイル（SearXNG の `settings.yml` をそのまま渡せる）、環境変数名（`SEARXNG_PORT` など）、対応するエンジンです。

違う部分は次のとおりです。

| 項目 | SearXNG | RustXNG |
|:--|:--|:--|
| 実装 | Python | Rust（単一バイナリ） |
| 画面のデザイン | 標準のテーマ | 独自（テーマは移植していない） |
| 画面の翻訳 | 60言語以上 | 57言語 |
| プラグイン | 12種 | 11種 |

結果の一致度は、README の実測で、hackernews と arxiv が完全一致、bing が88%でした。検索サイトの返事は時間で変わるため、同じ検索語で同じ並びになるとは限りません。

### 4.2 Google のような検索エンジンとの違い

RustXNG は自前の索引を持たず、問い合わせ先として用意されたサイトの一覧に収まる範囲だけを検索します。

## 5. 会話でわかったこと

### 5.1 検索できる範囲の決まり方

- 検索できるのは、エンジンが用意されたサイトだけで、ウェブ全体を直接たどるわけではない。
- 対象を増やす方法は2つある。用意済みで無効のエンジンを設定で有効にする方法と、エンジンを自分で書く方法である（書き方は CONTRIBUTING.md にある）。
- 226という数は、SearXNG が持つエンジンの数を、そのまま移植した結果である。「世の中の情報の何割を覆うか」という基準で選ばれた数ではない。
- 広さは Google、Bing、DuckDuckGo、Brave のような大手のウェブ検索が支え、深さは Wikipedia、arXiv、GitHub のような専門のサイトが足している。
- 検索できないものとして、ログインや有料が要る内容、大手の検索が拾っていない小さなサイトや新しいページ、公開されていない資料がある。

### 5.2 今後の拡張

- リリース記録では、最初の公開版で227種のうち156型が未移植だった。226種類の移植はv0.3.0で完了し、v0.4.0で前回の未移植項目が埋められた。
- 独自のサイトを足していく方針や、ロードマップは、読んだ範囲では見つからなかった。
- SearXNG に新しいエンジンが増えたとき、RustXNG が追いかけるかも、読んだ範囲ではわからない。

### 5.3 組織内のデータの検索

- 接続できる自前のデータ源として、PostgreSQL、MySQL、MariaDB、MongoDB、SQLite、Valkey、Elasticsearch、Solr、Meilisearch、recoll などが挙がっている。
- 検索の相手を自前のデータ源だけに絞れば、検索語と結果が組織の外に出ない形にできる。既定では約170の外部サイトに送るため、外部のエンジンを無効にする設定が必要になる。
- ファイルサーバーや SharePoint は、名前では挙がっていない。中身をいったん検索サーバー（Elasticsearch や Meilisearch など）に取り込み、それをつなぐ形になると考えられる（これは推測である）。取り込みは RustXNG の外で用意する必要がある。
- 速さは、つなぐ先の検索サーバーの性能に左右される。
- 利用者ごとに閲覧権限を分けられるかは、読んだ範囲に書かれておらず、確かめられていない。権限の分離が要る環境では、RustXNG 単体では足りない可能性がある。

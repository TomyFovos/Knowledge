# 生成AIの知財・透明性に関するプリンシプル・コード ナレッジ

調べた日：2026年10月31日

## 1. 概要

「生成AIの適切な利活用等に向けた知的財産の保護及び透明性に関するプリンシプル・コード」（以下、プリンシプル・コード）は、生成AIを外部に提供する事業者に、情報の公開と問い合わせへの回答を期待する国の指針である。2026年8月25日に知的財産戦略本部が公表した。

要点は次のとおり。

- 法的拘束力も罰則もないソフトローで、「実施するか、しない場合は理由を説明する」（コンプライ・オア・エクスプレイン）方式をとる
- 事業者は、自社サイトにモデルや学習データの概要を公開する（原則1）
- 法的手続きを行う、または準備している権利者と、生成した利用者からの問い合わせには回答する（原則2・3）
- コードを受け入れた事業者は内閣府に届け出ると、事業者名と公表サイトのアドレスが一覧に載る
- 内閣府は、届出内容とコードの整合性を審査しない

## 2. 理解に必要な前提

**ソフトローとコンプライ・オア・エクスプレイン**
法律のような強制力はないが、従わない場合に理由の説明が求められる形式の規範。日本では、上場企業向けのコーポレートガバナンス・コードが同じ形式である。

**情報の非対称**
これまで権利者は、自分の作品が学習データに使われたかを外から確認できず、事業者にも答える義務がなかった。コードは、この状況を減らすことを狙っている。

**営業秘密との両立**
学習データの構成やモデルの設計には、事業者の競争力を支えるノウハウが含まれ得る。そのため、全面開示ではなく「概要の公開」と「個別の問い合わせへの回答」に分けている。

## 3. 解説

### 3つの原則

| 原則 | 相手 | 内容 |
|---|---|---|
| 原則1 | 誰でも | コーポレートサイト等で、使用モデル、学習データに関する事項、アカウンタビリティ、知的財産権の侵害を防ぐ技術的措置の有無などの概要を公表する |
| 原則2 | 法的手続きを行っている、または準備している権利者等 | 権利者が照会したURL等の情報が、学習データセットに含まれているかなどを回答する |
| 原則3 | 生成AIでコンテンツを生成した者 | 開示を求められたら、原則2と同じ内容に回答する |

```
原則1：サイトで概要を公開（全員向け）
原則2：法的手続き中の権利者 → 事業者が回答
原則3：生成した利用者 → 事業者が回答
```

公開で全体の透明性を確保し、足りない部分を個別の問い合わせで補う二段構えになっている。

### 対象になる事業者

コードが想定しているのは、生成AIを開発して外部に提供する事業者である。弁護士事務所のセミナー資料は、次のように整理している。

- 受託開発だけを行う会社や、社内で生成AIを使うだけの会社は、定義上、対象外
- 自社データだけを使う社内AIやグループ内AIは、明文で除外されている
- 汎用モデルをベースに業界特化のAIをつくり、外部に提供すると、生成AI事業者にあたり得る

**オープンなモデルを追加学習して提供する場合（推測を含む）**
自分や自社だけで使うなら、社内利用にあたり対象外になると考えられる。追加学習したモデルを複数の相手に配布・販売するなら、外に出す側として対象になり得る。特定の依頼主だけのために追加学習して納品する場合は、受託開発として対象外と整理されている。

違いは、完成したAIを誰が外部の人に提供するかである。受託開発では提供するのは依頼主で、販売では作った会社自身が提供する。

### 届出の流れ

```
1. コードを受け入れ、自社サイトに開示内容を公表
2. 届出様式を内閣府の事務局に提出
3. 事務局が、事業を実際に行っているか、サイトに公表されているかを確認
4. 一覧に事業者名と公表サイトのアドレスが掲載される
```

- 届出様式の記入項目は、事業者名、代表者名、担当者の氏名・連絡先、公表サイトのアドレス
- 一覧で公表されるのは、事業者名とアドレスのみ
- 事務局は届出内容とコードの整合性を審査せず、第三者からの照会にも答えない
- 受付は2026年10月26日に始まった

届出は、許可を得る手続きではなく、受け入れたことを知らせる手続きである。罰則はない。届出が義務かどうかを明記した資料は、今回確認した範囲では見つからなかった。コードの性格から任意と考えられるが、確認できた事実ではなく推測である。

- 一覧に中身は書かれておらず、各社の開示ページへのリンクだけがある。実際の内容は、リンク先を開いて確かめる
- 載っていることは、内容が適切であることを意味しない（内閣府は審査しないため）
- 載っていないことは、違反を意味しない（届出は罰則のないもので、対象外の会社も多い）
- 一覧には、掲載準備のため届出から掲載まで時間がかかる場合がある、との注記がある
- 備考欄は、事業終了や名称・アドレスの変更があったときに使われる

## 4. 似たものとの違い

| 比較対象 | 違い |
|---|---|
| 法律（著作権法など） | プリンシプル・コードは強制力がなく、事業者の公開と回答への期待を示すもの |
| コーポレートガバナンス・コード | 形式は近い（ソフトロー、実施か説明）。対象は上場企業ではなく生成AI事業者 |
| 裁判での証拠開示（民事訴訟の制度） | 裁判の手続きの中で情報を得る仕組みで、強制力がある。コードは手続きの前後で任意の回答を期待する点が違う |

## 5. 会話でわかったこと

**何のための制度か**
権利者と事業者の間にある情報の差を減らすことが目的である。法律で全面開示を義務づけると企業の秘密を損ない、AI開発の力も削ぐおそれがある。そのため、罰則ではなく、一覧による見える化で事業者に対応を促す設計になっている。

**対象かどうかの境目**
境目は、AIを自分で使うか、外に提供するかにある。受託開発と販売の線引きも、完成したAIを外に出すのが誰かで決まる。ただし、受託でつくったものを後から横展開する場合など、境目の事例は確認できていない。

**届出の位置づけ**
届出は、事前の申請や許可ではない。「何かに引っかかるから出す」ものではなく、受け入れた事業者が自分から知らせる手続きと整理できる。

## 6. 未解決事項

- 受託開発と販売の境目にある事例（受託でつくったものの横展開など）の扱い
- 上流のモデル開発者と、追加学習して提供する事業者の責任の分担（追加学習した側が、元モデルの学習データをどこまで把握し、説明する必要があるか）。コード本文では確認していない
- 届出が義務かどうか、届出しない場合に求められる説明の程度
- コードの実効性。法的拘束力がないため弱いとする見方と、一覧による市場からの圧力で働くとする見方がある
- 原則2・3と既存の証拠開示制度との関係。BSAは、原則2・3が既存の証拠開示の手続きを迂回し、入力側の分析で、本来は出力側で判断すべき侵害の問題を解こうとしていると指摘している
- 営業秘密との線引き。どこまで開示するかは、各社の開示を通じて水準が固まっていく部分
- 一覧が5社から、どこまで広がるか

# TokenEconomizer ナレッジ

コーディングエージェントの費用を、過去のセッションからの学習で下げるプラグイン「TokenEconomizer」の解説です。調査日は2026年11月2日です。

この文書の書き分けは次のとおりです。

- 【確認済み】リポジトリのREADMEに書かれていたこと
- 【推測】READMEを読んだうえでの理解や推論。READMEでは確かめていません
- 【検討】調べる過程で出た論点と、その時点の答え

## 1. 概要

TokenEconomizer は、Microsoft Research と UC Berkeley の研究者が公開している、コーディングエージェント向けのプラグインです。

【確認済み】

- 対象は Claude Code、Codex、GitHub Copilot CLI、Pi の4つです。
- エージェント本体やモデルには手を入れません。同じリポジトリで過去に走らせたセッションから学び、次のセッションの無駄を減らします。
- 仕組みは3つあります。リポジトリの豆知識を伝える「Micro-skills」、使われないツールを外す「Tool pruning」、行き詰まったターンに介入する「Loop guard」です。
- 学習した内容は手元の `~/.tokeneconomizer` に保存されます。
- ライセンスは Apache-2.0 です。

【確認済み】論文での測定結果は次のとおりです。

- SWE-Bench の277タスク（6リポジトリ）を、5つのエージェントとモデルの組み合わせで評価しました。
- 平均費用が18.4〜30.9%下がりました。リポジトリ × 組み合わせの30通りすべてで、デフォルトより安くなりました。
- 成功率（Pass@1）は、5つのうち4つの組み合わせで上がりました。

## 2. 理解に必要な前提

**ハーネス**
モデルを包んで、ツールの実行、プロンプトの組み立て、会話履歴の管理をするプログラムです。Claude Code や Codex は、モデルとハーネスの組み合わせとして見られます。TokenEconomizer は、このハーネスを書き換えずに、ハーネスが用意した拡張口から働きかけます。

**フック**
ハーネスが、決まったタイミング（セッション開始、ツール呼び出しの前後など）で、外部のプログラムを呼び出せるようにした拡張口です。呼ばれたプログラムは、その時点の状況を見て条件を判断し、文脈に文章を足すなどの動作ができます。

**ツール定義とトークン費用**
エージェントは、使えるツールの定義（名前、説明、引数）を、毎回のリクエストに付けて送ります。使わないツールでも、定義の分だけ入力が増えて費用がかかります。

**プロンプトキャッシュ**
同じ前半部分のプロンプトを再送するとき、読み取りの価格が安くなる仕組みです。セッションの費用の大半は、このキャッシュの再読み込みです。ツールの構成を変えると、会話の履歴を最初から書き直すことになり、割高になります。キャッシュは一定時間たつと切れます。

**ターン**
1つの指示に対して、エージェントが作業するひとまとまりです。1つのセッションに、複数のターンが含まれます。

**Pass@1**
1回の試行で、タスクを解けた割合です。**SWE-Bench** は、実際のリポジトリの課題を解かせるベンチマークです。

**MCP サーバー**
エージェントに外部のツールを追加する仕組みです。Copilot CLI では、MCP サーバー単位でツールを外します。

## 3. 解説

### 3.1 狙い

【確認済み】同じエージェントを同じリポジトリで使い続けると、次の無駄が毎回繰り返されます。

- 同じ事実を調べ直す
- 使わないツールの定義を送り続ける
- 同じ失敗を繰り返して、ターンが行き詰まる

TokenEconomizer は、リポジトリごとに過去の記録から学び、この3つの無駄を減らします。

```
終わったセッションの記録
        ↓
リポジトリごとに学ぶ
（事実・不要なツール・行き詰まりのパターン）
        ↓
次のセッションが安くなる
```

READMEは、4つの原則を挙げています。

1. エージェントがもともと読むもの（開始時の文脈、設定ファイル）を通して働きかけ、エージェントに新しいツールを覚えさせない
2. キャッシュの料金で費用を数え、プラグイン自身のモデル呼び出しも含める
3. タスクの成功を守る（繰り返しの証拠があるものだけ採用する）
4. すべての動作を元に戻せるようにする

### 3.2 Micro-skills：リポジトリのやり方を覚える

【確認済み】リポジトリごとの事実を覚えて、セッションの開始時にエージェントへ伝えます。

覚える事実の例：

- 先に実行しないといけないビルド手順
- このリポジトリで動くコマンドの綴り（`pytest` がなければ `python -m pytest`、`tsc` がなければ `npx tsc`）
- コマンドに必要な環境変数
- 生成されたファイルの置き場所

事実の見つけ方は2つです。

1. 複数のセッションで繰り返された失敗から拾う
2. 3セッションごとに、モデルが最近のセッションを見直して候補を出す

```
失敗の繰り返し ─┐
                 ├→ 事実の候補 →（3セッションで確認）→ 開始時に伝える
モデルの見直し ─┘                         ↑
                    後のセッションで食い違えば取り下げ
```

- 3つのセッションで確認されて、はじめて伝えます。後のセッションで食い違いが出たら取り下げます。
- 初期設定ではオフです。経路2でモデル呼び出しが増え、節約額がリポジトリや作業で変わるためです。
- `microskills=envfacts` にすると、失敗の繰り返しだけから学びます。モデル呼び出しは増えません。

### 3.3 Tool pruning：使われないツールを外す

【確認済み】使われないツールを、次のセッションから読み込まないようにして、毎回のリクエストを軽くします。

外す条件は、次のどちらかです。

- 10プロンプトの間使われず、その10プロンプトが2セッション以上にまたがる
- 5セッションの間、長さを問わず使われない

長いセッションを重く数え、1つのセッションだけでは決めないための条件です。

外し方は、エージェント自身の設定ファイルへの書き込みです。外せる単位はエージェントごとに違います。

| エージェント | 外せるもの | 書き込み先 |
|---|---|---|
| Claude Code | 個別のツール | `.claude/settings.local.json` |
| Codex | 機能のパッケージ | `.codex/config.toml` |
| Copilot CLI | MCP サーバー丸ごと | `.github/copilot/settings.local.json` |
| Pi | なし（読み込むツールが4つだけ） | なし |

- 拒否リストは、そのリポジトリでの作業が60分止まってから書きます。ツールの構成が変わると、会話の履歴をキャッシュに書き直すことになります。1時間たてばキャッシュは切れているので、その損が出ません。
- `toolprune restore` で、プラグインが書いた分だけが消えます。利用者が書いた拒否ルールには触れません。一度戻したツールは、もう外されません。
- `toolprune=propose` にすると、提案だけ出します。`toolprune apply` を実行するまで、何も変えません。
- 設定ファイルをプラグインが新しく作ったときは、そのファイルを git の管理から外します（`.git/info/exclude`）。

### 3.4 Loop guard：行き詰まったターンに介入する

【確認済み】同じ失敗を繰り返しているターンを見つけて、別のやり方を試すよう促します。

```
ターンが失敗を繰り返す
        ↓
判定役のモデルが「行き詰まりか」を判断
        ↓ 確信度 0.7 以上
エージェントに短い注意書きを追加（別の方法を試して）
        ↓ それでも行き詰まり
利用者に「止め方」を知らせる（自動では止めない）
```

- そのリポジトリで、うまく終わったターン（最後の編集のあとに失敗するチェックがない）が5回たまるまでは、介入しません。たまると、そのリポジトリでの普通のターンの長さが分かります。
- 普通の長さの2.5倍を超えて、同じ編集と同じ失敗を繰り返しているターンは、判定役を通さずに注意書きを出します。
- 注意書きは、1ターンにつき最大1回です。
- それでも行き詰まっているときは、止め方を示す1行が出ます。ターンを止めるかどうかは、利用者が決めます。

出力の出方は、エージェントごとに違います。

| エージェント | 対話での表示 | 止め方 |
|---|---|---|
| Claude Code | Claude の返信の中 | Esc |
| Codex | 会話の中 | Esc のあと `/stop` |
| Copilot CLI | 会話の中 | Esc を2回 |
| Pi | 通知 | Esc |

- Claude Code は、プラグインの出力を詳細表示（Ctrl+O）にしか出しません。そのため、プラグインが Claude に1行を繰り返してもらいます。Claude が言い換えたり省いたりする可能性があります。
- ヘッドレス実行（`claude -p` など）では、誰も見ていないことがあります。印を付けられたターンは、自然に終わるか、エージェント自身の上限に達するまで走ります。

### 3.5 インストールと設定

【確認済み】

- 必要なもの：4つのエージェントのどれか（ログインの方式は問いません）と、Python 3.10 以上です。専用の API キーはいりません。
- Claude Code・Codex・Copilot CLI は、リポジトリをクローンしてマーケットプレイスとして登録し、プラグインを入れます。Pi は `pi install git:github.com/microsoft/TokenEconomizer` です。
- Claude Code と Copilot CLI では、マシンごとに1回、`toolprune refresh-catalog` を実行します。各エージェントの更新のあとにも、もう一度実行します。
- Codex は、フックを信頼する確認（Trust all and continue）が要ります。
- 初期設定は、Tool pruning と Loop guard がオン、Micro-skills がオフです。
- この初期設定では、モデルが呼ばれるのはターンが行き詰まりそうなときだけです（判定役と、注意書きの作成）。
- 設定は `config set` で変えます。1セッションだけ切るときは、`TE_DISABLE=1 claude` のように環境変数を付けます。
- `status` で、学んだ内容、行った動作、費用が確認できます。

対応バージョンは次の範囲です。READMEによると、各範囲の最古と最新で動作を確かめた状態で、それより新しい版は未確認です。

| エージェント | 対応範囲 |
|---|---|
| Claude Code | 2.1.300〜2.1.310 |
| Codex | 0.153.1〜0.164.0 |
| Copilot CLI | 1.0.83〜1.0.102 |
| Pi | 1.2.0〜1.3.0 |

## 5. 会話でわかったこと

### 5.1 どこに置くのか（ハーネスへの組み込みか、中継か）

【確認済み・READMEからの読み取り】ハーネスの中身を書き換える形ではなく、エージェントの拡張口に載る形です。モデルとハーネスの間に入る通信の中継（プロキシ）でもありません。

```
┌─ エージェント（ハーネス、無改造）──────────┐
│  セッション開始 ← フック①：事実を文脈に追加   │
│  ツール呼び出し ← フック②：失敗を監視         │
│  設定ファイル  ← ③：拒否リストを書き込む     │
└───────────────────────────────┘
        ↕ 呼び出し／ログ読み取り
  ローカルの Python プログラム（~/.tokeneconomizer）
```

置き場所は3か所です。

1. フック：セッション開始時や各ツール呼び出しのタイミングで、ローカルの Python が呼ばれます。
2. 設定ファイル：Tool pruning が拒否リストを書きます。
3. セッションのログ：終わったセッションのログを読んで学びます。

判定役などのモデル呼び出しは、利用者のエージェントを経由して、同じ契約やログインのまま走ります。

### 5.2 フックで入れる場合の条件

【確認済み】

- フックが使えるバージョンでしか動きません。たとえば Codex は 0.141.0 より前だと、フックが動きません。
- Python 3.10 以上が必要です。
- エージェントによっては、初回に信頼の確認や `refresh-catalog` の実行が要ります。

【検討】フックは、条件を見て動けるため、失敗の繰り返しを見て介入する Loop guard のような使い方に向いています。ローカルに入れられますが、「すぐ入る」のは対応バージョンの範囲内に限られます。

### 5.3 エージェントごとの違いと、自作ハーネスへの適用

【確認済み】フックの呼び出し方、設定の書き込み先、外せるツールの単位、ログの形式、通知の出方は、エージェントごとに違います。リポジトリの `trace` が、各エージェントのログを1つの形に読み替えています。中核は共通で、つなぎ込みの部分をエージェントごとに作っている構成です。

【推測】自作のハーネスへは、READMEで対応と書かれていないので、そのままは動きません。次の3つがあれば、同じ考え方でつなげられる可能性があります。

1. 開始時と各ツール呼び出しで、外部プログラムを呼べるフック
2. 開始時に、文脈へ文章を足せること
3. 読み取れるセッションのログ

中核の Python は標準ライブラリだけで書かれているので、再利用はしやすそうです。つなぎ込み用のコードは、自分で書くことになります。流用の範囲は、`tokeneconomizer/` の中身を読まないと断言できません。

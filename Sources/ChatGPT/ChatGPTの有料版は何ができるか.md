# ChatGPTの有料版は何ができるか

会社からChatGPTの有料版が支給されても、これまでChatGPTを使ってこなかった人にとっては、「無料版と何が違うのか」「仕事で何に使えばいいのか」が分かりにくいと思います。

実際、ChatGPTは普通に質問するだけでも便利ですが、有料版で使える機能まで含めると、できることはかなり広がります。

資料をまとめて渡して考えてもらったり、時間のかかる調査を任せたり、実際のリポジトリを使って開発してもらったりと、「質問に答えてもらう」以外の使い方もできます。

せっかく会社から使える環境が用意されるので、まずはどんなことができるのかを知って、使えそうなものを一つでも試してもらえればと思います。

ここでは、無料版との細かな機能差を一つずつ並べるのではなく、仕事で使ったときに違いを感じやすいものを六つにまとめます。

## 1. 難しい仕事ほど、ChatGPTに投げてみる

ChatGPTは、簡単な質問に答えてもらうだけのものではありません。

会社から支給された有料版では、より高性能なモデルや強い推論機能を使えるため、条件が多い仕事や、すぐには答えが出ない問題も相談しやすくなります。

たとえば、長い資料を読んで内容を整理してもらったり、複数案を比較して判断材料を出してもらったり、エラーの原因を調べてもらったりできます。

設計方針や実装方針のように、いくつもの条件を踏まえて考える必要がある仕事も、最初から全部自分で整理するのではなく、ChatGPTと一緒に考えられます。

### 一口メモ

簡単な質問だけに使うのは、少しもったいないと思っています。

「これ、整理するの面倒だな」「条件が多くて考えるのが大変だな」と感じる仕事ほど、そのままChatGPTに渡してみると、使いどころが見えてきます。

## 2. 資料、コード、ログは、必要な部分を切り出さずに渡してみる

ChatGPTには、PDF、Word、Excel、CSV、画像、スクリーンショット、ソースコードなどをそのまま渡せます。

たとえば、仕様書とソースコードを一緒に確認してもらったり、ログとエラー画面を合わせて原因を調べてもらったり、複数の資料を比較してもらったりできます。

有料版では、より多くの情報を扱えるため、渡した情報の一部しか見てもらえずに回答されることが減り、全体を把握したうえで考えてくれるようになります。

エンジニアの仕事では、該当するメソッドだけを見ても原因が分からず、その周辺の処理や仕様、ログまで確認しなければならないことが珍しくありません。

そういうときに、自分で「ここが怪しいはず」と範囲を絞ってから質問するのではなく、判断に必要そうなものをまとめて渡せるのはかなり便利です。

### 一口メモ

以前は、ChatGPTに見せるために必要そうな部分を自分で抜き出していました。

今は、仕様書、コード、ログなどをまとめて渡して「この全体を見て考えて」と頼むことが増えています。

自分で原因の場所をある程度特定してから質問しなくてもよくなるので、調査の最初から使えます。

## 3. 調べものは、検索結果を集めるところから任せてみる

Webで情報を探すとき、自分で検索して、何ページも開いて、必要な情報を拾ってから整理する作業は意外と時間がかかります。

ChatGPTのDeep Researchを使えば、複数のWebサイトや資料を調べ、情報を比較したうえで、調査結果としてまとめてもらえます。

調査した内容を文章にまとめたり、その内容に合わせて説明用の画像を作ったりするところまで、そのまま続けることもできます。

「検索ワードを考えるところまでは自分でやる」という使い方から離れて、調査そのものを仕事として渡せるようになります。

### 一口メモ

何かを調べるとき、私は最初からGoogleを開くとは限らなくなりました。

「これについて調べて、違いを比較して、参考にした情報も付けて」と頼めるので、自分で検索結果を何十個も開くより楽な場面があります。

調査に時間がかかりそうな仕事ほど、一度試してみてほしい機能です。

## 4. エンジニアなら、Codexは一度触ってみてほしい

ChatGPTにコードを貼り付けて、「このコードを説明して」「このエラーの原因は何？」と質問したことがある人は多いと思います。

Codexでは、そこからさらに進み、実際のリポジトリを対象に開発作業を任せられます。

たとえば、「この不具合を直して」と依頼すると、関連するコードを探し、原因を調べ、修正方針を考え、実際にコードを変更してテストまで進める、といった流れを扱えます。

新しい機能の実装、リファクタリング、テストの追加、コードレビュー、Issueを起点にした調査や実装にも使えます。

コードの書き方を教えてもらうだけではなく、開発作業そのものを分担できるのがCodexです。

### 一口メモ

エンジニアなら、まずCodexを一度触ってみてほしいです。

コードを貼って質問するChatGPTとは、かなり使い方が違います。

「この不具合を調べて」と渡すと、リポジトリを読んで原因を探し、修正し、テストまで進めてもらえるので、AIが開発に入ってくる感覚を一番つかみやすい機能だと思っています。

## 5. 毎回ゼロから説明せず、仕事ごとにChatGPTを育てて使う

ChatGPTには、プロジェクト、メモリ、スケジュールなど、継続して使うための機能があります。

プロジェクトを使えば、案件やシステムごとに資料や会話をまとめておき、その前提を共有した状態で相談を続けられます。

そのため、新しいチャットを開くたびに「このシステムはこういう構成で、今こういう問題があって」と最初から説明する必要が減ります。

定期的に同じ情報を調べてもらったり、決まったタイミングで知らせてもらったりする使い方もできます。

### 一口メモ

一回質問して終わる使い方だけだと、ChatGPTは便利な検索のように見えます。

案件ごとにプロジェクトを作って資料や前提を持たせておくと、毎回説明し直さなくてよくなるので、「この仕事のことをある程度知っている相手」に相談する感覚へ変わっていきます。

## 6. 社内の情報を、自分で集めてから貼り付けなくてもよくなる

会社向けのChatGPTでは、管理者が許可した範囲で、普段使っている社内サービスや情報源と接続できます。

メール、カレンダー、社内資料、社内ナレッジ、GitHubなどにつながれば、「ChatGPTに聞くために必要な情報を自分で集める」という準備そのものを減らせます。

たとえば、「以前この件についてやり取りしたメールを探して」「このプロジェクトに関係する資料を確認して」「GitHubの実装を調べて」といった依頼を、そのままChatGPTに渡せます。

会社向けのChatGPTは、単に個人版より高性能なAIを使えるだけではなく、普段の仕事で使っている情報とつながることで、仕事の入り口から使えるようになるのが大きな特徴です。

### 一口メモ

個人的に期待しているのは、ChatGPTそのものが賢くなること以上に、普段使っている仕事の情報につながることです。

メールや資料を探して、必要なところをコピーして、それからChatGPTに相談するのではなく、「必要な情報を探すところからお願い」と言えるようになると、使い方はかなり変わると思っています。

## まずは、この6つのどれかを試してみてほしい

| こんな仕事があったら | 試してみること |
|---|---|
| 考えるのが大変な仕事 | 条件をまとめて渡して、そのまま相談する |
| 資料やログが多い調査 | 必要そうなものをまとめて渡す |
| 調べものに時間がかかる | Deep Researchに調査を任せる |
| 実装や不具合調査がある | Codexにリポジトリごと渡す |
| 同じ案件を何度も相談する | プロジェクトを作って継続して使う |
| 情報を探すところから面倒 | 社内サービスとの連携を使う |
